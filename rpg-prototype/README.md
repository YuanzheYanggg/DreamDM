# 地球之外 · 雾港手记

本地 HTML RPG 试玩。玩家点击选项推进故事，状态、能力、背包和旅程同步更新。保留原来的离线示例，并加入真实 Codex/Astra + Jev 主持模式。

## 启动

推荐 Node.js 24（需内置 `node:sqlite`），不需要安装 npm 依赖。在 DreamDM 仓库根目录运行：

```sh
node rpg-prototype/server.mjs
```

打开 <http://127.0.0.1:4317/>。只监听本机。端口占用时可用 `RPG_PORT=4318 node rpg-prototype/server.mjs`；离线示例的浏览器存档按端口隔离，AI 存档保存在本机数据库。

AI 模式另需本机 `codex` CLI 已登录且可用 `gpt-6-astra`，以及通过 `TYPESAFE_API_KEY` 环境变量或 macOS 钥匙串服务 `typesafe-ai-project-test` 配置的 Jev 凭证。凭证只由服务器读取，网页不会拿到密钥。其他机器的安装与凭证引导尚未打包。

## 开始试玩

点击页顶「AI 主持」，选择初始幸运值，再开始旅程。第一次会调用 Astra high，一次备好所有场景、选项、后果和三个结局，再由 Astra 复核（生成、审查各一次，均计入开局额度）。准备成功后缓存在本机；后续新旅程复用已审核原章。

- 普通选择：Jev 从已审核的候选中选择后果，不额外掷幸运。
- 风险选择：Jev 在一次请求里回答 Score、Noul 和条件 Choice。服务器将坏／中／好的分布归一化至 100%，用一次保存的运势值和角色幸运修正选定档位，再执行该档位中的后果。
- 幸运 50 为中性；0–100 对运势的修正为 −10 到 +10 百分点。概率为零的档位不能被幸运强行打开。界面可展开查看基础分布、实际分布、运势和判定时间。
- 每个后果都附带未来状态投影。Noul 判断是否超出预写路线的覆盖范围，Choice 指明具体缺口；只采用实际发生后果的建议。有免费补救路线、普通数值变化，都不触发改写；不因好运或坏运而补偿性改判。
- 一次结果可以同时改变数值、开启渡鸦支线、积累后续条件。合流保留这些差异。极少数确有未覆盖的必要条件时，先保存当前结果，再交 Astra high 形成主线调整建议；当前固定图原型只保存建议，不自动插入新节点或修改效果。
- 可手动要求 Astra low／medium／high 改写未来文案；生成后仍由 Astra 审查，通常各占同一档位的一次额度。只在来源状态未过期、草稿仍适用于抵达状态时发布，Jev 不审核稿件。迟到稿沿用既有内容。
- 普通选择仍需等一次 Jev 网络响应；玩家不需要等待 Astra 临时写下一幕。开局准备与逐回合判定耗时分开记录。
- 页面刷新恢复服务端进度。重复点击不重复结算；失败不自动重试，明确重试沿用同一份已生成运势。模型服务可能收费，调用数可在存档页查看。

## 整局预算与裁定边界

按约 100 次剧情选择预留 **Jev 130 次、Codex/Astra 18 次**。Jev 分为预检 6、行动 100、阶段复核 4、恢复 20；Astra 分为开局 4、low 6、medium 4、high 2、审稿修复 2。服务器在发送前原子预占额度，失败和运行中尝试都计数，各用途不能借用。刷新、重启和导入存档不补满；已有旅程后明确开始新一局才创建新账本。这个上限约束请求次数，不是固定金额，也不是必须花完的配额。详见 [预算方案](../docs/rpg/2026-09-22-session-budget.md)。

Astra 对开局剧本和未来草稿承担一致性审查，要求逐项结论及真实原稿/规则引文；未通过的内容不发布。相同稿件已收到的审查结果会缓存，重试不会重新抽取结论。Jev 不再回答 `consistent`、`consistency_case` 或 `patch_consistent`，也没有终局绕过审核的例外规则。

Jev 的 Noul 只影响未来规划调度：达到 0.85 且对应明确、未被兜底路线覆盖的需求，才请求 Astra high。此阈值是暂定调度策略，未通过玩家数据校准；它不裁定当前选择能否执行。当前分支 Choice 或风险 Score 格式错误仍会保留进度并报错，缺失可选规划回答则不撤销合法结果。人物资源和物品前提由本地程序校验。

保留历史预算及调用记录，不追溯改写旧审批依据。旧 Jev 开局预检额度目前不自动使用；两次 Astra 开局调用取自原有 opening 额度。高档主线建议每次一个请求；手动未来文案生成加审查通常两个请求。本局剩余额度没有重新分配或补满。

人物卡展示生命、精力、压力、身手、洞察、交涉、意志、幸运及背包。干粮可在本地消耗并恢复精力。前期借据、线索与人情可影响档案馆入口；开锁失败后仍可向值夜人求助。渡鸦约定在后面回收，三个结局由玩家选择。

## 存档和数据

「存档」支持导出／导入本章 AI 旅程，以及切回原离线示例。下载按钮之外也提供可复制的存档文字。本轮下载文件落盘是否成功须看 [QA.md](QA.md) 的实际验证范围。

AI 状态、生成剧本、一次性运势、结算事件和请求回执保存在仓库根目录的 `runs/rpg-live/state.sqlite`；WAL 辅助文件属于同一数据库。请求记录包含发送的游戏状态、结果和耗时，不保存凭证。不要在分享代码时把个人数据库一起打包。

网页仅接收当前可见故事与人物状态，不直接提供 AI 后续剧情、服务端模块或 SQLite 文件。显式导出的存档包含完整章节以便离线恢复；它不是加密的防剧透格式。原离线示例的 `story.mjs` 仍随前端提供，因此本试玩不声称对本机玩家隐藏世界设定。

## 当前范围

这是六场景的接入验证，完整通关约 5–6 次选择。Astra 创作文案、Jev 裁定条件后果、本地代码执行固定机制。后台可发布经 Astra 审查的未来场景文字，并保存罕见的主线重规划建议；尚不能把建议编译为新剧情节点或机械效果。

尚未实现约 100 次选择的长篇、通用世界包、人格建档、长期因果方案的自动执行，以及可下载安装的 skill bundle。Jev 的分布是模型判断，未用玩家数据校准；Astra 审稿与引文存在性验证也不等于剧情绝对正确。

名字、角色林照及雾港世界都是可修改的示例。「雨中微寒」等状态目前主要参与叙述／Jev 上下文，不额外暗扣本地能力；渡鸦的银羽有明确临时意志效果。

## 文件与检查

- `index.html`、`styles.css`、`app.mjs`：界面与双模式交互。
- `game.mjs`、`story.mjs`：原离线示例及共用物品／时钟定义。
- `live/world.mjs`：有限世界规则、动作、后果和生成结构。
- `live/engine.mjs`：Jev 问题、幸运分布、合法后果与状态结算。
- `live/authoring.mjs`：Astra 作者审查、证据验证与稿件签名。
- `live/providers.mjs`：真实 Jev API 和无工具、临时 Codex 进程。
- `live/runtime.mjs`：SQLite、请求去重、任务恢复、后台稿件与存档。
- `live/budget.mjs`：版本化整局配额、用途隔离、原子预占和历史记账。
- `server.mjs`：同源 API 与静态文件白名单。
- `QA.md`：实际验证与范围限制。

在仓库根目录运行 `npm test`；测试使用注入的本地答案，不触发真实模型。DreamDM 不包含金铲铲控制代码。
