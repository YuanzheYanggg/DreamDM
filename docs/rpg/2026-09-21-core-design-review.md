# 核心思路审查：幸运、Jev 判定与异步剧本

> 本审查后的用户修订已整合至 `2026-09-21-dm-logic-v3.md`。其中固定 D20 决定成败是当时的建议，已由用户明确的 Score 分布与幸运区间机制替代。

日期：2026-09-21。性质：针对运行设计 v2 的设计分析与修正建议，尚未实现或经过真实游戏验证。

用户新增要求：骰子是玩家幸运的一种体现，骰子和幸运应当作为 Jev 输入的一部分。本次先审查核心思路，不继续接入代码，不调用付费游戏判定或生成。

## 判断

“预先建立世界与大纲 + Jev 每回合多问题裁定 + Astra 按影响范围后台改写”可作为原型方向。主要问题不在模型能否接起来，而在谁有权决定什么、如何保证多个答案组合后的因果一致，以及新内容准备不足时如何兑现玩家的选择。

需要优先修正：幸运与骰子的含义；成败与语义后果的边界；Jev 长期判断的实际范围；并行问题的联合约束；内容缓冲和改写调度。low / medium / high 只是生成配置，不能单独解决这些问题。

## 1. 骰子可以传给 Jev，但要让它真正影响规则

三个变量分别表示：

- 幸运属性：角色长期具备的优势或劣势，由世界规则决定其作用。
- 本次骰子：在这一次行动上实现的随机结果，不能用一次高点数倒推角色长期更幸运。
- Jev 概率：模型对候选判断的分布，不等于角色幸运或实际掷骰结果。

相同公平 D20 的点数分布对所有人相同；如果幸运属性只写进提示词，却没有明确改变检定或事件规则，就不能保证这个属性有可理解、可验证的效果。

### 三条可选路线

| 路线 | 优点 | 主要代价 |
| --- | --- | --- |
| 骰子仅作语境，Jev 综合决定成败 | 叙事裁量较大，容易表达复杂场景 | 难以保证幸运有效、装备有用和相同条件公平，骰子可能沦为装饰 |
| 规则固定机械结果，Jev 选择符合语境的合法后果 | 概率、成长与装备效果清楚，同时保留叙事反应空间 | 需要明确规则和候选；推荐首版采用 |
| Jev 先估计成功概率，再由程序抽样 | 可容纳难以公式化的行动 | 模型概率需要领域验证，措辞与版本可能影响结果；若判定时见到骰子还可能形成事后裁量 |

推荐第二条。将幸运属性、骰子、修正来源和已计算的结果档位一起传给 Jev；Jev 必须遵守已确定的档位，并判断“这一档结果具体如何发生”。

示例公式仅用于讨论，未作为已批准的游戏数值：

```text
检定值 = D20 + 对应能力 + 工具修正 + 环境修正 + 有上限的幸运修正
```

假设难度 14、能力 +3、工具 +2、湿滑环境 −2：幸运修正 0、+1、+2 时，均匀 D20 的成功率分别为 50%、55%、60%。已枚举全部 20 个点数核对，未运行真实游戏。自然 1/20 的特殊规则、部分成功区间若需要，必须另行事先定义。

这说明幸运如何影响机会；不能为了“玩家很幸运”又让 Jev 额外提高成功档位或免掉已规定代价。若同一回合还要对另一件事独立应用幸运，要明确那是另一次事件检定，避免同一个幸运加成在多个层次反复生效。

### 必须满足的约束

- 难度和修正规则先确定，再抽随机数；不能看到点数后改难度。
- 普通走路、资源足够的普通购买直接完成，不为制造戏剧性增加失败骰。
- 世界规则不允许的行动不因高点数突然成立；有条件的奇迹需要世界事先允许。
- 相同条件和骰子下，提高幸运不能降低机械检定档位。幸运不能保证每一种道德选择或故事结果都让玩家满意。
- 幸运不能无成本同时替代身手、交涉、洞察等所有专长。修正上限、成长成本、适用范围需要平衡；可消耗幸运点是后续备选机制，首版不必同时引入。
- 同一个行动的重试、刷新和断线恢复复用已经登记的骰子。重复点击不重新抽取，也不重复扣资源。

## 2. Jev 不适合每回合重新推演整个故事

运行设计 v2 中“判断长期走向”如果理解为重新预测整部小说，范围过大。TypeSafe 官方将这类原语描述为针对给定上下文的快速、聚焦判断，并建议将需要复杂推理的任务分解。[依据](https://docs.typesafe.ai/primitives)

建议大纲提前声明：

```text
归还名字这一条路线，需要：借名簿仍存在 + 守钟人愿意或能够解读
守钟人退出，会影响：档案馆会面、仪式教学、守钟人相关结局
借名簿销毁，会影响：证据展示、归还仪式、债务追溯
```

明确状态变化由程序沿依赖关系查找受影响节点。Jev 处理尚不能直接查表的语义判断，例如“这次承诺是否构成背叛”“该 NPC 根据自己所知是否会退出合作”。新出现、未建模的复杂因果交 Astra 复核和规划。

拆分为：已知依赖查找、语义条件判断、新因果规划。不能只通过把全剧本塞给 Jev 来同时满足深推演与低延迟。

## 3. 多问题并行不等于答案彼此协调

官方说明，同批问题看到相同 state，但独立评估，一个问题的答案不是另一个问题的隐藏上下文。[依据](https://docs.typesafe.ai/primitives)

设计风险例子：一个答案说商人没看见偷窃，另一个说他当场因亲眼看见而报警；或者结果说没拿到借据，背包变化却增加了借据。

推荐采用以下顺序：

1. 用规则排除不可能结果，固定本次检定档位。
2. 将不能拆开的事实组成少量完整结果候选，例如“拿到借据且未被发现”“拿到借据但被发现”。
3. 对真正独立的问题并行提问；对依赖结果的问题明确写成“若候选 A 生效……”的条件问题。
4. 只采用实际候选对应的条件答案，程序检查物品守恒、目击情况、人物知识、代价范围和节点条件后统一提交。

不能把多个边缘概率相乘就当成合理的联合世界，也不应先独立随机抽出许多答案再靠写作解释冲突。八个二元结果若全排列，会有 256 种组合；增加问题不是没有结构成本。

本地检查能证明预设约束成立，不能证明故事语义永远正确。遇到未覆盖组合，需要保留原状态、记录具体原因；不能静默改骰子或修改玩家选择来凑出一个可执行结果。

## 4. 世界事实、NPC 所知和玩家所知必须分开

主持系统知道某人是窃贼，不代表商人知道。把全知信息直接用于 NPC 反应，很容易产生“每个人都读懂玩家内心”的世界。

至少区分真实事实、各角色已知或相信的内容、玩家已知内容。每个关键事实带来源或触发事件；谣言、猜测和事实分开记录。真假翻转可以是对先前传闻的揭示，不能悄悄把已确认为真的历史改掉。

Jev 判断人物反应时只使用该人物有理由知道的信息及其目标。Astra 改写也需要遵守相同边界。

## 5. 后台生成不会自动消除等待

如果玩家刚使守钟人死亡，而下一幕预写的是守钟人当面教学，那么“high 正在后台改写”不能让旧场景继续成立。

v2 中“每个结果都有到本章末的路线”应理解为：有条件的节点和备用路径通过可达性检查。它不应变成预写所有未来完整文本的笛卡尔积。假设每节点四个选择、每选择三个结果，完整展开两步就有 144 个叶节点；这是组合计数，不是模型性能实测。

推荐短期准备充分、长期保留结构：

- 近处节点已有叙述、合法结果和下一步行动；远处保留大纲、人物目标与依赖。
- 使用可复用场景与有条件合流，但每条入口带来的关系、物品、伤亡和承诺不能被清零。
- 已展示选项的即时后果和本章可完成路径必须已备好。新重大选项在可游玩承接内容准备好后才发布。
- 高影响变化若使旧路线失效，立即隔离旧节点；只走与新事实相容的储备内容。
- 在明确章末可以展示准备状态。不能承诺在有限预算、任意快点击下无限提供全新内容且永不等待。

每次选择后调用 Jev 意味着即时链路仍有网络与推理等待。可以测量和优化，不能以官方并行宣传或另一个应用的最快样本替代本游戏的点击到画面更新数据。

## 6. Astra 档位和调度紧急程度是两件事

“大改用 high，小改用 low”可以保留，但只知道改动大小不足以决定什么时候开始做。

| 判断 | 用途 |
| --- | --- |
| 影响范围 | 选 none / low / medium / high，确定允许修改的区域 |
| 最早失效节点 | 知道玩家多快会撞到旧剧本不再成立的位置 |
| 当前可玩储备 | 判断还有多少合法节点可供继续游玩 |
| 新补丁的前置事实 | 检查生成期间状态变化后，补丁还能否发布 |

某句下一幕对白的 low 修改可能很紧急；数章之后的 high 修改可能有充分时间。由程序根据已知节点和依赖计算能确定的部分，Jev 标记语义不确定之处。

后台结果提交前检查它依赖的事实和目标节点，而不是看到全局版本变过就全部丢弃，也不能无条件覆盖。互不相关的新背包操作不应让全部写作报废；相关 NPC 死亡则必须使依赖其存活的补丁失效。

## 7. 守住主线，不等于守住唯一过程与结局

若所有选择最后都被改写成同一条路线，数值变化与奇异文案不能补偿玩家影响力不足。若允许任何变化，又要求每个既定场景都发生，大纲会自相矛盾。

建议固定世界规律、核心冲突和已发生事实；开放解决路线、人物关系、参与阵营与结局条件。为每个关键选择规定至少一个可追踪的持续后果，普通动作不必每次改动历史。

候选行动即使奇异，也需要让玩家理解自己的意图以及大致的成本或风险。不能所有选项都像开盲盒，导致人物属性、信息搜集与策略失去作用。对危险且不可逆的结果，应在选择前给出符合角色知识的预兆。

失败应有实际代价，某些机会可以失去。允许故事继续不代表每次失败都换个措辞获得同样奖励。持续把失败修成成功会使骰子失去意义。

## 8. 伏笔需要因果依据，不能全部强制回收

伏笔台账需要区分：已埋设、玩家是否注意到、何时适用、已回收、错失、失效。记录它第一次出现的具体事实、关联对象及可回收条件。

允许后来赋予旧细节新意义，前提是不违反旧描写；不能声称玩家曾读过一段实际未出现的文字。关键线索、角色承诺与纯氛围细节也应区分，避免每一个物件都变成天命道具。

玩家可以错过支线、拒绝奇遇、让某条承诺无法完成。这些也能形成有意义的经历，不需要 Jev 把所有伏笔硬拉回主线。

## 9. 幸运、奖励与奇遇还涉及长期平衡

即使每次奖励都不越界，连续奖励也可能使资源失去意义；每个事件单看合理，连续发生也可能让世界过度戏剧化。

需要跨回合记录奖励与损耗、稀有事件频率、追踪或压力累积、幸运修正使用范围。冷却和节奏限制由公开的世界设计原则控制，不能为了戏剧性偷偷在玩家点数很好时降低成功率。

Jev 的 confidence 根据输出分布计算，不是已校准的正确率。随机趣味与判断不确定性分开处理：低 confidence 不能被解释成“更有随机乐趣”，关键事实冲突不能通过抽样消除。[依据](https://docs.typesafe.ai/confidence)

## 10. 下载 skill 与能够持续运行游戏是两个交付层次

skill 适合保存规则、世界创作规范、问题模板和主持流程；网页点击、持久状态、随机数、后台任务、版本冲突处理还需要实际本地运行器。

可分发包应包含 skill、运行器和世界包规范。在线模型服务仍需要使用者自己的可用登录或凭据及相应使用额度；当前机器鉴权成功不代表别人下载后无需配置即可运行。凭据不能装进分发包。

导入世界需要检查 schema、版本、引用和可运行条件。世界包是游戏数据，不得拥有修改本机凭据、执行任意代码或改变运行器权限的能力。

## 11. 性格推断的定位

最初提出的“反推性格”适合先做成可修改的游玩偏好，例如偏好探索、风险、关系经营或推理。玩家会扮演与自己不同的人物，选择也受当时选项限制，不能直接当作真实人格结论。

如果系统据早期选择持续只提供同一类型选项，就会制造“越来越确定玩家只有这种偏好”的循环。保留多样选择，允许玩家调整偏好；角色性格和玩家口味分开保存。未经玩家提供的历史不能假设可读取。

## 12. 接入前最值得验证的情境

| 情境 | 要成立的性质 |
| --- | --- |
| 同一行动、同一骰子，提高幸运 | 机械检定档位不降低，作用可解释 |
| 不可能的行动得到最大点数 | 不违反世界规律 |
| 普通行动 | 费用足够就执行，不平白制造检定障碍 |
| 偷窃的物品、目击与报警判断 | 组合后的事实相容，NPC 不读取全知信息 |
| 关键 NPC 退出 | 所有依赖其存活的可见未来节点失效，已有兼容路径可承接 |
| 早期借据或承诺在后期触发 | 能找到真实的先前事件及触发条件 |
| 玩家拒绝奇遇或错过线索 | 不强制重演同一事件，不偷偷改写历史 |
| 快速连续选择、生成很慢或失败 | 记录真实缓冲情况；不撤销选择，不伪装已准备好 |
| 断线、重复点击、后台结果过时 | 不重掷骰、不重复扣资源、不覆盖新事实 |
| 一轮高 confidence 但事实矛盾 | 程序仍拒绝非法组合 |

先做一个短篇章节，实际包含普通行动、概率检定、一次伏笔回收与一次会影响人物线的选择。对比纯规则与 Jev 裁定在合理性、差异性、延迟和调用成本上的表现；不要预先认定接入 Jev 就必然更好玩。

本次完成的是上述设计审查和公式枚举。尚未实现这些约束，也未进行真实游戏模型调用或长篇压力测试。
