# Codex + Jev 主持接入（早期方案，已被替代）

> 用户随后明确：先有大纲与可玩剧本；每次选择后 Jev 批量回答多个问题；Astra 只在后台按 low / medium / high 改写未来内容。当前设计见 `2026-09-21-dm-runtime-v2.md`。下文逐回合等待 Codex 生成的流程不再作为实现依据。

用户已要求接入真实 Codex 和 Jev，沿用已接受的 HTML 外观。此阶段只实现单玩家主持循环，不扩展人格建档、世界编辑器或多人游戏。

## 分工与请求

- Codex CLI 使用本机已有 ChatGPT 登录，以 `gpt-6-astra` 生成结构化场景、3–4 个行动选项及各自允许的后果。使用临时工作目录、只读沙箱、禁用 shell/apps/多代理/搜索，不读取游戏之外的工作区资料。
- 日常行动有一个明确后果，本地结算，不调用 Jev。
- 困难行动在展示前固定能力、难度和资源消耗；本地 D20 决定结果档位；Jev 从该档位的两个后果中选一个，也可返回信息不足。模型概率不充当骰子概率。
- 后果包含有界的生命/精力/压力/铜币变化、已有物品的增减、已知事实与伏笔回收。本地验证后才可执行。
- 每次推进最多一次 Jev 请求和一次 Codex 生成；应用和 Codex provider 重试关闭。失败后的重新尝试由玩家明确点击。

## 存储与边界

- 服务器保存完整主持状态和每次调用的游戏证据；前端只获取公开角色、物品、历史、场景和行动。
- API key 仅由服务器读取钥匙串，Codex 使用自己的登录；不把凭据给页面或游戏模型。
- 回合带版本，服务端只允许一个进行中的请求，重复提交与旧场景点击不再请求模型。
- 保存尚未完成的回合阶段和已得到的 Jev 判定。后续叙事失败时保留判定和骰子，显式重试只继续尚未完成的部分。
- 原示例存档保留，AI 旅程使用独立服务器存档。新旅程创建新文件，不覆盖旧旅程。
- 完整 AI 存档可通过压缩编码导出和导入；这用于避免直接展示未揭晓剧情，不是防作弊或加密承诺。

## 界面

沿用故事、旅程、人物和背包。页顶显示当前为 AI 主持或示例剧本；存档菜单提供模式切换、新旅程、导出和恢复。等待时显示当前阶段，刷新后可继续等待；失败时显示重试入口且不扣资源。

## 实现顺序

1. 添加主持输出契约、世界规则、状态结算与测试。
2. 添加 Codex CLI / Jev provider 适配器和无自动重试策略。
3. 添加持久化运行器、同源 HTTP 接口、版本检查和失败续接测试。
4. 将现有页面接到服务端状态，保留示例模式。
5. 先跑离线检查，再在 3 次 Codex / 2 次 Jev 的验证上限内完成一次真实页面循环，记录实际延迟与调用次数。
