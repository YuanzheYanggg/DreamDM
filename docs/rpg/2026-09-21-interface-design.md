# Earth Online：本地 RPG 界面设计草案

日期：2026-09-21。状态：用户已选择先实现可玩的界面原型；真实模型接入留给后续阶段。

## 已确认的玩法

- 游戏以可分享的本地 Codex skill bundle 为载体，世界与剧本可以导入、导出。
- 玩家从 AI 提供的若干选项中行动；不以自由文本作为主要行动入口。
- Astra 负责世界规划、场景、选项和叙事；Jev 在当前状态及允许的结果范围内裁定。
- 选项可以奇异、发散，但应遵守世界法则、人物知识和已发生的事实。
- 主线维持核心矛盾和关键事实；玩家可以通过不同路径推进并改变结果。
- 早期选择、伏笔和钩子能在后期影响事件及可选行动。
- 用户希望用简单 HTML 界面展示故事、选择、人物能力、物品和状态，增强代入感。

## 界面方案

推荐采用以阅读为中心的布局：宽屏上主区展示场景与行动，侧栏展示角色；窄屏上优先故事与选择，角色信息通过折叠区访问。

另两种可行布局是全屏单栏故事配角色抽屉，以及传统多面板 RPG 控制台。前者阅读最专注，但角色变化不够直观；后者常驻信息多，对本次简单 HTML 的目标偏重。

主界面保留四种内容：

1. 当前场景：世界名、地点、故事内时间、场景标题、叙述和 NPC 对话。
2. 行动选择：通常 3–5 项，文案直接描述行动；必要时展示角色已知的消耗、前提或风险。
3. 角色面板：姓名、身份、能力值、身体与精神状态、货币、背包。
4. 旅程记录：已做出的选择、已获知的线索、承诺、关系变化，以及已揭示的伏笔回收。

选项只展示玩家可知的信息；不把隐藏后果、幕后真相或未来剧情暴露为选项说明。

## 能力与状态

能力是相对稳定的角色特征；状态是会随行动改变的短期资源或影响。两者应分开显示。

示例能力可包含体魄、身手、洞察、交涉、意志和奇术。具体名称与量表由世界包定义，不强制所有世界沿用同一组能力。

示例状态包括生命、精力、压力，以及受伤、被追踪、某种祝福等有持续时间或解除条件的效果。界面应能解释效果实际影响的能力或行动。

每次正式结算后展示简短变化，例如“精力 −2”“获得：无名旧信”“与摆渡人的关系改善”，并与最新角色数据一致。

## 背包

物品至少展示名称、数量和玩家已知的说明。可用物品只显示当前允许的操作，使用、装备、丢弃等行为仍通过统一行动机制结算。

物品的秘密用途保存在主持状态中。描述不能提前标注“最终章关键物品”或“尚未回收的伏笔”。

## 回合交互

1. 展示当前已经发布的场景和选项。
2. 玩家点击一次选项，界面锁定本回合其他提交并展示等待状态。
3. 主持层根据当前存档版本处理选择并返回结算。
4. 校验通过后，一次性更新场景、角色、背包、经历和存档版本。
5. 展示变化摘要和新的选项。

失败或断线时保留上一份有效状态，不提前扣物品或资源。重复点击不能重复结算；旧场景的选项不能被用于新场景。

“实时”在首版中指每次行动结算后同步更新；不要求角色在玩家离线时自动推进。

## 公开状态与主持状态

前端只接收玩家视图：当前场景、可选行动、人物公开数据、已知物品、已知关系和经历。

主持层单独保存世界真相、NPC 隐藏目标、事件条件、未揭示的伏笔和候选后果。不能先把这些内容发送给前端再依赖 CSS 隐藏。

角色数值与背包以同一份已结算状态为依据，不从叙述文字中重新猜测。

## 本地载体

界面可以使用 HTML、CSS 和少量 JavaScript，无需先引入大型前端框架。

独立界面原型可用示例剧本和浏览器本地存储验证交互。真正连接 Codex/Astra/Jev 时，需要本地运行器承接玩家选择、主持任务和存档；HTML 本身不能保证唤醒或持续运行 Codex。

模型凭据不进入页面或导出的世界与存档。完整运行模式下，世界内容由主持层组织后发送给相关模型服务。

## 首版验证场景

- 正常选择推动故事，角色状态与背包同回合更新。
- 某个前期选择在后期解锁专属选项，并能从经历记录中找到依据。
- 刷新后恢复当前场景，已获得物品不会重复领取。
- 同一选项快速点击两次只结算一次。
- 导出个人存档后可恢复原来的角色、物品和经历。
- 小屏上故事和所有行动仍可阅读、点击，没有水平溢出。
- 示例剧本、真实模型调用和当前未连接能力在交付说明中如实区分。
